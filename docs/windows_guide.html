Private Air-Gapped AI Workspace on Windows PowerShell with Codex CLI

A practical Windows workflow for fine-tuning a local OSS model on private workspace-derived data, serving it locally, and using it safely through Codex CLI.

1. What This Setup Does

This setup gives you a strong local-only workflow:

  • Codex CLI runs locally on Windows
  • the model is served locally through Ollama or LM Studio
  • your workspace is scoped to specific directories
  • sandboxed shell commands can be denied network access
  • you can fine-tune a local OSS model on private workspace-derived data
Important: --oss does not by itself create a true air gap. A true air-gapped workflow also requires web search off, no remote MCP usage, and host-level network isolation.

2. Core Concepts

Codex CLI

Codex CLI is the local terminal agent. It reads, edits, and operates on files inside the workspace you expose to it.

--oss

--oss tells Codex to use the local open-source model provider. In the current Codex CLI, the local providers are ollama and lmstudio.

network_access = false

This controls whether sandboxed model-generated shell commands can use the network. It is an important local-only control, but it is not the full air-gap boundary by itself.

Workspace Scoping

Codex does not automatically train itself on your workspace. You give it access to a workspace for the current session:

codex --oss -C C:\SensitivePatent
codex --oss -C C:\SensitivePatent --add-dir C:\ResearchDocs

This is session context, not permanent model learning.

Fine-Tuning

Fine-tuning happens outside Codex. You adapt a local model, serve it locally, and then point Codex at that served model.

3. LoRA and QLoRA

  • LoRA = Low-Rank Adaptation
  • QLoRA = Quantized Low-Rank Adaptation

On Windows, QLoRA is usually the better starting point if you are fine-tuning on consumer GPU hardware.

4. Recommended Architecture on Windows

  1. Prepare a base open-source model locally
  2. Convert your private workspace into a supervised fine-tuning dataset
  3. Fine-tune locally, usually in WSL with NVIDIA CUDA support
  4. Merge or keep the adapter
  5. Serve the resulting model locally through LM Studio or Ollama
  6. Use Codex CLI in PowerShell with --oss and -m to connect to that local model
Boundary: WSL or Linux tooling is the practical fine-tuning path on Windows. LM Studio or Ollama is the local model server Codex connects to.

5. Recommended Hardware

Fine-tuning on Windows is most practical with an NVIDIA GPU, WSL2, recent CUDA-compatible drivers, and enough disk for models and checkpoints.

If you do not have an NVIDIA GPU, fine-tuning is usually much slower and less practical.

6. Installation

Install Codex CLI

npm install -g @openai/codex
codex --version

Install Python

python --version

Install WSL

wsl --install
wsl -l -v

Install a Local Model Server

Install either LM Studio or Ollama. Codex currently expects the local OSS model to be served through one of these providers.

7. Prepare Before Disconnecting from the Network

Download everything first while still online:

  • Codex CLI
  • Python
  • WSL and Linux toolchain
  • fine-tuning packages
  • the base model
  • LM Studio or Ollama

Only then should you disconnect the machine from the network if you need strict isolation.

8. Choose a Base Model

Start with a manageable instruct or coding model such as a 7B or 14B model. Use larger models only if the hardware can support them.

9. Prepare the Fine-Tuning Dataset

Do not point the trainer at a folder and expect it to learn the repo automatically. Fine-tuning requires a curated JSONL dataset.

Recommended Format

{"messages":[
  {"role":"system","content":"You are an expert assistant for this private codebase."},
  {"role":"user","content":"Explain how the job scheduler works."},
  {"role":"assistant","content":"The scheduler coordinates queued tasks by..."}
]}

Create a Dataset Directory

New-Item -ItemType Directory -Force -Path C:\airgap-ft\data

Suggested files:

  • C:\airgap-ft\data\train.jsonl
  • C:\airgap-ft\data\valid.jsonl
  • C:\airgap-ft\data\test.jsonl

10. Fine-Tuning Path on Windows

The practical path is to use PowerShell for Windows-side setup, WSL for the fine-tuning run, and then serve the resulting model locally on Windows.

11. Fine-Tune Locally in WSL

python3 -m venv ~/ft-env
source ~/ft-env/bin/activate
pip install --upgrade pip

Then run your chosen LoRA or QLoRA training stack. General shape:

python train.py \
  --model /path/to/base-model \
  --train-data /mnt/c/airgap-ft/data/train.jsonl \
  --valid-data /mnt/c/airgap-ft/data/valid.jsonl \
  --output-dir /mnt/c/airgap-ft/output \
  --lora

12. Test the Fine-Tuned Result

Verify that held-out examples improve, that private domain tasks are handled better, and that the model is not simply overfitting the prompts.

13. Package the Model for Serving

Import the trained model into LM Studio or create/import it into Ollama. Codex does not load arbitrary raw checkpoints directly by itself.

14. Use the Fine-Tuned Model with Codex CLI

codex --oss --local-provider ollama -m your-finetuned-model -C C:\SensitivePatent
codex --oss --local-provider lmstudio -m your-finetuned-model -C C:\SensitivePatent

--oss selects the local OSS provider, --local-provider selects LM Studio or Ollama, -m chooses the served model, and -C sets the primary workspace.

15. Recommended Secure Codex Settings

codex `
  --oss `
  --local-provider ollama `
  -m your-finetuned-model `
  -C C:\SensitivePatent `
  --sandbox workspace-write `
  --ask-for-approval on-request
model_provider = "oss"
oss_provider = "ollama"
model = "your-finetuned-model"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
web_search = "disabled"

[sandbox_workspace_write]
network_access = false

16. Important Security Boundaries

  • --oss means local model provider
  • network_access = false means sandboxed shell commands cannot use the network
  • neither of those alone guarantees a true physical air gap

For a true air-gapped workflow, also isolate the host machine, disable remote integrations, and avoid any sync tool that can move data off the device.

17. Fine-Tuning vs Retrieval

Fine-tuning is best for style, behavior, and transformation habits. Retrieval is better for frequently changing files and exact recall from current documents.

18. Minimal End-to-End Workflow

  1. Install Codex CLI, WSL, the fine-tuning stack, and a local model server
  2. Download the base model while still online
  3. Build a clean JSONL dataset from the private workspace
  4. Disconnect the machine from the network
  5. Fine-tune in WSL with LoRA or QLoRA
  6. Test the adapter or merged model
  7. Package the model for LM Studio or Ollama
  8. Serve it locally
  9. Launch Codex with --oss -m ...
  10. Work inside the scoped private workspace

19. Example Session

codex `
  --oss `
  --local-provider ollama `
  -m patent-coder-private-v1 `
  -C C:\Users\You\Documents\SensitivePatent `
  --add-dir C:\Users\You\Documents\PatentResearch `
  --sandbox workspace-write `
  --ask-for-approval on-request

Inside Codex, use /status to verify the model, sandbox settings, and writable roots.

20. Final Takeaway

  • Codex scopes and uses your local workspace
  • WSL-based tooling fine-tunes a local model on a curated dataset derived from that workspace
  • LM Studio or Ollama serves the resulting model locally
  • --oss and network_access = false support a strong local-only workflow
  • host-level isolation is still required for a true air gap

Prepared as a practical guide for Windows PowerShell local-only development and sensitive workspace handling.
